Problem

The question worth solving.

On a cut, logging every meal gets tedious fast, and food, workouts and weight usually end up in three different apps.

User workflow

From problem to system.

I built the app around a quick daily loop: type or dictate a meal in English or Chinese, check the parsed foods, save, and see what is left for the day. Workouts, weigh-ins and the calorie budget live on the same overview.

Inside the workflow

Text is matched against a built-in food list with USDA reference values, so logging works offline and without an account. Nothing is saved until the portions are confirmed. The day's calorie budget follows the logged training: rest, strength, basketball, or both.

Output & value

What a logged day looks like

The overview compares calories, protein, carbs and fat with the day's targets and lists the meals so far. Progress and calendar views add the weight trend with a 7-day average, weekly to quarterly calorie summaries, and CSV export.

Technical implementation

Technologies & methods

Records are saved on the device first. With Supabase configured, each account syncs across devices. Server routes add USDA FoodData Central search, text and photo meal parsing through an OpenAI-compatible API, and a token-scoped API (with an OpenAPI spec and an MCP bridge) for logging meals and workouts from other tools.

  • USDA FoodData Central

Scope & limitations

Portions and calorie burn are estimates, and log dates use Pacific Time. The live demo runs entirely in the browser with sample data and keeps records on your device; cloud sync, USDA search, AI meal parsing and the API need your own keys when you host it. No user study or weight-loss result is claimed.
