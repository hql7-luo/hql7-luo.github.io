What to Eat Today

A local meal decision tool: five preferences, explainable rules, a weighted draw, and a recommendation with reasons.

Problem

The question worth solving.

Routine meal decisions consume time and repeat the same recent choices.

User workflow

From problem to system.

I built the preference flow, constraint-based scoring and fallback, a weighted draw, recommendation explanations, and browser state persistence.

Inside the workflow

Rules exclude yesterday’s accepted dish and downweight meals from 2–3 days ago to 0.35. The animation reveals a result already selected by the weights; no machine learning is used.

Output & value

More about the recommendation design

Five inputs filter and score 92 local dishes. The output includes a dish and its reasons, followed by confirmation, redraw, favorites and local history. Shops are manually saved reminders and do not affect recommendation weights.

Scope & limitations

Dish recommendations only: no nearby-restaurant search, live delivery data or ordering. All personal records stay in the current browser. Dish imagery is representative AI artwork, not restaurant photography. No user study or measured behavioral improvement is claimed.
