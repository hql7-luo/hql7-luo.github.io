LLM Selection & ROI for Export Inquiries

Which LLM should an export sales team use, and is it worth paying for?

A decision case for a fictional Chinese exporter of printing consumables that gets about 500 inquiries a month. An LLM drafts each tracker entry and a salesperson checks it.

The short answer

Pick the cheapest model that does well on your own inquiries. Here that was Claude Haiku 5.5: no critical errors in 160 tries, about $714 a month ahead, and a 2.8-month payback.

AI drafts pay off while fewer than about 17% of inquiries have a critical error. All eight models were under that line; simple rules without AI (20%) were not. For a team that prefers a mainland provider, DeepSeek V4 Pro also made no errors.

What I did

I chose the question from my 2026 export work, set the scope (two tasks, one prompt for every model, a no-AI baseline), decided how to test models without an API key, and reviewed the results and conclusions. Claude substantially assisted the research, data, code and writing; Codex and WorkBuddy ran the GPT, DeepSeek and Kimi tests.

Business problem

Every inquiry is typed in by hand, and good leads can wait.

A small Chinese exporter of printing consumables and packaging gets about 500 inquiries a month by email, Alibaba and chat. A salesperson reads each one, types the product, spec, quantity, target price, Incoterm, destination and delivery date into a tracker, and decides which to answer first.

An LLM could draft that entry for a person to check. The questions are which model to use, and whether the time saved is worth more than the API bill and the cost of the model's mistakes.

What I did

My Approach

  1. Build 100 labeled inquiries: 60 regular ones (8 in Russian), 25 hard cases written by hand and 15 traps such as spam and fee scams. 20 were used to write the prompt and rules; 80 were kept for testing.
  2. Score every answer field by field. A critical error is a wrong product, spec, quantity, target price or delivery date, an invented item, or a good lead ranked lower.
  3. Test a no-AI rules baseline and eight models without an API key: three Claude models as subagents, two GPT models in Codex, and DeepSeek and Kimi in WorkBuddy. Each answered the same 80 inquiries twice, 20 at a time, in sessions that could not see the answer key.
  4. Turn error rates into money: labor saved, minus API cost, minus the extra cost of mistakes compared with a person working alone. Find the break-even error rate and check that the Python model and the web calculator agree.

The company and inquiries are fictional, and labor and error costs are labeled assumptions, so the numbers show the shape of the decision, not measured savings.

Key findings

What the Test Showed

$42a month per point of critical error rate, vs. a $3 price gap between models
20%critical error rate for simple rules without AI (55% on hard inquiries)
  • One debatable inquiry caused all of Sonnet's, Sol's and DeepSeek V4.1 Flash's errors: a Russian request for thermal CTP plates with no size or thickness. The answer key was set before any model ran and was not changed.
  • Kimi's errors were mostly good leads ranked too low (17 of 19). Each time it marked the lead medium because the Incoterm, destination or delivery date was missing, which the rule does not require.

Recommendation

Recommendation

Start with the cheapest model that passes a test on your own inquiries. Here that is Claude Haiku 5.5. If the team prefers a mainland provider, DeepSeek V4 Pro or V4.1 Flash did as well, but confirm them through DeepSeek's own API first.

Keep the human check. It is what keeps the cost of mistakes low, and the reviewer's catch rate moves the answer more than any other input.

Before choosing for real

  • Test 50 to 100 real, anonymized inquiries; the synthetic set is too easy to separate the top models.
  • Time 10 inquiries by hand and 10 AI reviews to replace the minutes assumptions.
  • Count how many AI errors reviewers catch in the first month.
  • Try working out priority in code from the extracted fields, since it follows a fixed rule.

Fictional company; model estimates, not measured savings. Not financial advice.

Methods & limitations

How the numbers were built

Net per inquiry = labor saved minus API cost minus extra error cost. Labor saved comes from manual minutes, review minutes and the time to fix the errors a reviewer catches. Extra error cost is the errors that slip past review, minus the mistakes a person would make alone, times the cost of one escaped error.

Base case: $9.70 an hour (Hangzhou salary from Liepin plus overhead), 6 minutes by hand, 1.5 to review, 80% of AI errors caught, 2% manual error rate, $40 per escaped error, 500 inquiries and $50 maintenance a month, $2,000 setup. API costs are list-price estimates.

Checks: 26 automated tests, including that the answer key follows the written rules, that run files match the saved raw replies, and that the web calculator matches Python.

Scope & limitations

The inquiries are synthetic and were written with Claude's help, which may favor Claude.
